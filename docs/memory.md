# Shared Project Memory (Phase 7)

AI Supervisor features an authoritative, provenance-aware, local-first Shared Project Memory subsystem located in `memory/` and `core/memory/`.

## 1. Core Invariant

> **"Agents are replaceable. Project knowledge should not be."**
> **"Memory is NOT automatically truth. Every memory item must carry provenance and epistemic status."**

An external agent stating a hypothesis or claim does NOT make it a verified fact. The Supervisor maintains strict epistemic custody over project memory:
* Claims from agents are recorded as `UNVERIFIED`.
* Hypotheses disproven by verification are recorded as `REJECTED` (with failure details) so no subsequent agent repeats them.
* Only objective, empirical evidence (passing tests, compiler output, worktree git inspection) promotes a memory to `VERIFIED`.

---

## 2. Memory Architecture & Lifecycle

```text
Event / Claim / Discovery / Verification
                     ↓
             Memory Candidate
                     ↓
        Sanitization (Secret Scrubbing)
                     ↓
               Provenance Tagging
    (source, source_id, created_by, evidence)
                     ↓
               Status Determination
       (VERIFIED / INFERRED / UNVERIFIED / REJECTED)
                     ↓
        Deterministic Content Deduplication
       ((project_id, normalized_content) index)
                     ↓
           SQLite WAL Persistence
         (table: memory_records)
                     ↓
       Deterministic Ranked Retrieval
    (Project Scope + Trust Hierarchy + Task Match)
                     ↓
       Bounded Agent Memory Context
         (ProjectMemoryContext)
```

---

## 3. Domain Model & Knowledge Taxonomy

Located in `memory/models.py`:

### Memory Types (`MemoryType`)
* **`FACT`**: Factual propositions about the codebase, dependencies, protocols, or architecture.
* **`DECISION`**: Confirmed architectural or policy choices made by the operator or supervisor.
* **`CONSTRAINT`**: Scoping boundaries, forbidden edits, or hard budget restrictions.
* **`FAILURE`**: Task-level execution anomalies or test suite failures.
* **`REJECTED_APPROACH`**: Hypotheses or strategies demonstrably attempted and disproven.
* **`DISCOVERY`**: Useful codebase patterns or diagnostic findings identified during task runs.
* **`TASK_CONTEXT`**: Ephemeral objective context bound to a specific task.
* **`VERIFICATION_RESULT`**: Empirical reports generated by the Phase 4 Independent Verifier.

### Epistemic Status (`MemoryStatus`)
* **`VERIFIED`**: Supported by objective independent empirical evidence (e.g. tests passing, exit code 0).
* **`INFERRED`**: Synthesized from multiple observations but not directly proven.
* **`UNVERIFIED`**: Agent self-assessments or unproven claims.
* **`REJECTED`**: Disproven hypotheses or failed approaches retained so subsequent workers avoid them.
* **`OBSERVED` / `DECIDED` / `STALE`**: Preserved for operational continuity and screen rendering.

### Provenance (`MemoryProvenance`)
Every persistent memory record explicitly tracks:
* **`source`**: Originating layer (`verification_engine`, `watchdog_event`, `agent_event`, `handoff`, `routing`, `user_input`, `system_observation`).
* **`source_id`**: Associated UUID (`verification_id`, `handoff_id`, `event_id`, `task_id`).
* **`created_by`**: Agent or subsystem that generated the claim (`claude_code`, `codex`, `verifier`, `supervisor`).
* **`evidence`**: List of objective proof lines (e.g. test assertions, git status porcelain lines, exit codes).

## 4. Trust Hierarchy & Ranked Retrieval

When an agent requests context or a query is executed, records are ranked deterministically:

$$\text{Score} = \text{TrustWeight} + \text{TaskMatchBonus} + \text{KeywordOverlapBonus} \times \text{Confidence}$$

### Trust Weights
1. **`VERIFIED`**: `+5.0`
2. **`DECIDED`**: `+4.0`
3. **`OBSERVED`**: `+3.0`
4. **`INFERRED`**: `+2.0`
5. **`UNVERIFIED`**: `+1.0`
6. **`REJECTED`**: `0.5` (Excluded from active facts, but explicitly surfaced in `rejected_approaches`).

### Task Match Bonus
`+3.0` if `record.task_id == query.task_id`.

### Keyword Overlap Bonus
`+2.0` per intersecting token between query keywords and memory content/details.

### Recency & Determinism
Ties are broken deterministically by UTC creation timestamp, followed by lexicographical record ID. Randomness is prohibited.

---

## 5. Strict Project Scoping

Memory never leaks across distinct codebases. Every record carries a `project_id`. When querying:
* Queries with `project_id="auth_service"` strictly filter out records belonging to other projects (`billing_service`, `data_pipeline`, etc.).
* Sub-project tasks can further narrow scope using `task_id`.

---

## 6. Deterministic Deduplication & Immutability

* **Deduplication Key**: `(scope_key, _normalize_content(text))` where normalization lowercases, strips punctuation, and collapses whitespace.
* **Epistemic Promotion**: When a candidate with higher certainty (e.g., `VERIFIED`) is recorded for an existing `UNVERIFIED` fact, the existing record is updated in-place with the verified status, upgraded confidence, and new provenance proof lines.
* **Audit Preserved**: History is never silently erased. Conflicting or superseded facts record a `superseded_by` pointer.

---

## 7. Engine Integrations

### Handoff Integration (Phase 5 + Phase 7)
When a task is handed off from a failing agent (e.g. Claude) to a recovery agent (e.g. Codex), `HandoffEngine` queries `MemoryStore.build_project_memory_context(...)`:
* Receiving agent context package includes all `VERIFIED` facts and decisions discovered so far.
* Receiving agent context package includes explicit `DO NOT REPEAT` warnings for every `REJECTED_APPROACH`.
* Unrelated project memories are filtered out.

### Verification Engine Integration (Phase 4 + Phase 7)
Upon completion claim inspection:
* If the verifier makes an `ACCEPT` decision: It calls `record_verified_fact(...)`, promoting the outcome to verified project memory.
* If the verifier makes a `REJECT` decision: It calls `record_rejected_approach(...)`, documenting the failed approach and test output.

### Routing Engine Integration (Phase 6 + Phase 7)
`RoutingEngine.collect_agent_metrics()` queries project memory to factor in historical verified successes vs rejected approaches attributed to each candidate agent.

---

## 8. Security & Sanitization

1. **Secret Redaction**: Every memory entry is passed through `sanitize_text()`, which scrubs OpenAI keys (`sk-...`), Anthropic keys, GitHub tokens (`ghp_...`), GitLab tokens, and bearer passwords before writing to SQLite WAL.
2. **Untrusted Claims**: Agent claims cannot self-verify, cannot escalate execution permissions, and cannot bypass worktree isolation or watchdogs.
3. **Control-Plane Authority**: The Supervisor and Independent Verifier remain the sole authorities for status promotion to `VERIFIED`.

---

## 9. SQLite WAL Persistence

Memory is persisted in table `memory_records`:
* `record_id` (PRIMARY KEY)
* `project_id` (Indexed)
* `mission_id` (FOREIGN KEY $\to$ `missions`, Nullable for global project facts)
* `task_id` (Indexed)
* `category` (Legacy tag)
* `content` (Sanitized text)
* `memory_type` (Indexed: `FACT`, `REJECTED_APPROACH`, etc.)
* `status` (Indexed: `VERIFIED`, `UNVERIFIED`, etc.)
* `confidence` (REAL)
* `source`, `source_id`, `created_by` (Provenance)
* `superseded_by`
* `metadata` (JSON containing extended details and evidence list)
* `created_at`, `updated_at` (ISO-8601 strings)

## 10. Concrete Code Example

```python
from memory import MemoryStore, MemoryStatus, MemoryQuery

store = MemoryStore(repository=memory_repo)

# 1. Record an agent claim (stored as UNVERIFIED)
claim = await store.record_unverified_claim(
    mission_id="msn_101",
    project_id="auth_service",
    task_id="tsk_01",
    content="Token validation fails due to UTF-8 BOM prefix",
    created_by="claude_code",
)
assert claim.status == MemoryStatus.UNVERIFIED

# 2. Independent verification confirms the claim with test evidence
verified = await store.record_verified_fact(
    mission_id="msn_101",
    project_id="auth_service",
    task_id="tsk_01",
    content="Token validation fails due to UTF-8 BOM prefix",
    source="verification_engine",
    source_id="ver_202",
    created_by="verifier",
    evidence=["pytest tests/test_auth.py: PASS"],
)
assert verified.id == claim.id
assert verified.status == MemoryStatus.VERIFIED

# 3. Build bounded memory package for Codex during handoff
pkg = await store.build_project_memory_context(
    mission_id="msn_101",
    project_id="auth_service",
    task_id="tsk_01",
    task_objective="Fix auth token parsing",
)
# Codex receives verified facts and avoided approaches without redundant rediscovery
```
